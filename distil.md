
Суть дистилляции (knowledge distillation) — в **переносе знаний от большой, точной модели («учителя») к маленькой, быстрой («ученику»)**. Цель — получить компактную модель, которая работает почти так же хорошо, как громоздкая, но при этом быстро инферится, потребляет мало памяти и подходит для edge-устройств.

Ключевая идея: вместо того чтобы учить ученика только на изначальных метках из разметки (hard targets, например, [0, 0, 1]), мы используем ** вероятности от учителя** (soft targets). Эти вероятности несут **дополнительный контекст**: например, учитель может сказать, что объект — это «90% кошка, 8% рысь, 2% собака», а не просто «кошка».

Это особенно ценно, когда классы семантически близки: soft targets показывают **относительные связи между классами**, которые hard targets скрывают.

Для обучения ученика мы минимизируем **KL-дивергенцию** между его выходным распределением $q$ и распределением учителя $p$:

$
\mathcal{L}_{\text{distill}} = \text{KL}(p \parallel q) = \sum_i p_i \log \frac{p_i}{q_i}
$

На практике часто используют **сигмоиду/softmax с температурой**, чтобы сделать распределение ещё более пологим:

$
p_{i} = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}
$
где $T > 1$ — температура, а $z_i$ — логиты.

Почему это лучше, чем учить на разметке?
— Hard targets несут **недостаточно информации об объекте**: «это класс 3».  
— Soft targets от учителя несут **дополнительные контекст**: «это класс 3, но похож на 5 и 7, и совсем не похож на 9».  
Эта информация помогает ученику обучиться эффективнее, особенно при малом объёме данных.

Часто итоговый лосс — это гибрид:

$
\mathcal{L} = \alpha \cdot \text{KL}(p_{\text{teacher}} \parallel p_{\text{student}}) + (1 - \alpha) \cdot \mathcal{L}_{\text{CE}}(y_{\text{true}}, p_{\text{student}})
$

где второе слагаемое гарантирует, что ученик не оторвётся от истинной разметки.

```python
import torch
import torch.nn.functional as F

# Логиты учителя и ученика
logits_teacher = torch.tensor([[2.0, 1.0, 0.1]])  # уверен в классе 0
logits_student = torch.tensor([[1.5, 1.2, 0.8]])

# Температура
T = 2.0

# Soft targets от учителя
p_teacher = F.softmax(logits_teacher / T, dim=1)

# Предсказания ученика (для дистилляции — тоже с температурой)
p_student = F.softmax(logits_student / T, dim=1)

# KL-дивергенция (в PyTorch: F.kl_div принимает log-probs!)
loss_kl = F.kl_div(
    torch.log(p_student),
    p_teacher,
    reduction='batchmean'
)
print("Loss дистилляции:", loss_kl.item())

# При обучении ученика этот лосс штрафует отклонение от "знания" учителя,
# а не только от жёсткой метки [1, 0, 0].
```

Итог: дистилляция — это не сжатие модели, а **передача семантического знания**. Ученик учится не просто угадывать метки, а **думать как эксперт**.


-----

Почему просто не разметить учителем все данные и учить на этом модель, зачем нужна дистиляция?
Дистилляция особенно полезна, когда у нас миллионы неразмеченных изображений — мы не можем разметить их вручную, но можем прогнать через учителя и дообучить студента. Даже при наличии идеальной разметки, студент, обученный через дистилляцию, иногда обобщает лучше, потому что учится тонкой семантике, а не просто запоминает метки.

 ------

 Какую задачу решает декодер в трансформере

1. Декодер генерирует выходную последовательность пошагово, предсказывая следующий токен на основе уже сгенерированных
2. Он использует два типа внимания: Masked self-attention — чтобы видеть только предыдущие токены (авторегрессивность), Cross-attention — чтобы обращаться к скрытым состояниям энкодера (контекст входной последовательности)

 Декодер в трансформере решает задачу **авторегрессивной генерации последовательности**. То есть он строит выход по одному токену за раз: сначала предсказывает первый, потом — второй, используя уже сгенерированные, и так до конца в цикле `for _ in range`. Именно так работают модели машинного перевода, генерации текста, речи и т.д.

Главное ограничение: на шаге `t` декодер **не должен видеть будущие токены** (иначе будет жульничество). Чтобы этого добиться, используется **masked self-attention** — особый вид внимания, в котором маска закрывает всё, что находится правее текущей позиции.

```python
# Пример: у нас уже сгенерировано ["<sos>", "I", "love"]
# Декодер обрабатывает всю эту последовательность, но при предсказании
# следующего токена (например, "ML") может смотреть только на "<sos>", "I", "love"
# — не на то, что будет дальше (потому что его ещё нет).

# Маска выглядит так (для 4 токенов, включая <sos>):
# [[1, 0, 0, 0],
#  [1, 1, 0, 0],
#  [1, 1, 1, 0],
#  [1, 1, 1, 1]]
# Где 1 = можно смотреть, 0 = закрыто
```
Роль `cross-attention` в классическом `encoder-decoder`. Но современные LLM это преимущественно только Decoder часть, там нет енкодера, а значит и нет смысла в `cross-attention`. За исключением таких моделей как `T5` (текстовая LLM с енкодер-декодер архитектурой, используется в text2image диффузионнке FLUX), `Qwen-VL`(мультимодальная vision LLM).
Продолжаем про оригинальный трансформер. Нам нужно ещё лучше **понимать контекст входа**. Для этого в оригинальном декодере использует второй механизм: **cross-attention**. Через него он на каждом шаге «заглядывает» в **выходы энкодера**, то есть в обогащённые представления исходной последовательности. 

Например, при переводе фразы "Я люблю машинное обучение" → "I love machine learning":
— энкодер обработал всю русскую фразу и сохранил смысл каждого слова в векторах,
— декодер, генерируя слово "machine", через cross-attention может сфокусироваться именно на слове "машинное", а не на "Я" или "обучение".

```python
# В архитектуре (например, в PyTorch или Hugging Face) это выглядит так:
# decoder_layer(
#   tgt=decoder_input,          # уже сгенерированные токены
#   memory=encoder_output,      # выход энкодера — контекст
#   tgt_mask=causal_mask        # маска для masked self-attention
# )

# tgt — это то, что генерирует декодер (target),
# memory — это выход энкодера (source representation)
```
Таким образом, декодер сочетает две вещи:
1. **Историю собственного вывода** (через masked self-attention),
2. **Контекст входной последовательности** (через cross-attention).

```python
# Пример запуска декодера трансформера в PyTorch

import torch
import torch.nn as nn

# Гиперпараметры
d_model = 512      # размерность скрытых состояний
nhead = 8          # число голов внимания
num_layers = 1     # один слой для простоты
batch_size = 2
tgt_len = 4        # длина уже сгенерированной последовательности (например: ["<sos>", "I", "love", "ML"])
memory_len = 6     # длина последовательности от энкодера (например, исходное предложение)

# 1. Выход энкодера (memory) — контекст входной последовательности
encoder_output = torch.rand(batch_size, memory_len, d_model)

# 2. Вход декодера (tgt) — уже сгенерированные токены (в embedding-пространстве)
decoder_input = torch.rand(batch_size, tgt_len, d_model)

# 3. Создаём слой декодера
decoder_layer = nn.TransformerDecoderLayer(
    d_model=d_model,
    nhead=nhead,
    batch_first=True  # чтобы размерности были [batch, seq, feature]
)

# 4. Собираем causal mask для masked self-attention
# Эта маска гарантирует, что на позиции i модель видит только токены 0..i
tgt_mask = nn.Transformer.generate_square_subsequent_mask(tgt_len)

# 5. Прогоняем через декодер
# Он использует:
#   - decoder_input и tgt_mask → для masked self-attention,
#   - encoder_output → для cross-attention
decoder_output = decoder_layer(
    tgt=decoder_input,
    memory=encoder_output,
    tgt_mask=tgt_mask
)

print("Форма входа декодера:", decoder_input.shape)      # [2, 4, 512]
print("Форма выхода энкодера:", encoder_output.shape)   # [2, 6, 512]
print("Форма выхода декодера:", decoder_output.shape)   # [2, 4, 512]

# На практике этот выход подаётся в линейный слой → logits → следующий токен
# Процесс повторяется до генерации <eos>
```

Без masked self-attention генерация была бы неавторегрессивной (и, скорее всего, бессмысленной).  
Без cross-attention декодер не знал бы, что именно переводить или о чём генерировать.

В современных моделях (например, GPT) энкодер отсутствует — там только декодер, и он генерирует текст, опираясь исключительно на предыдущие токены. А в моделях типа BART или T5 — полная архитектура: энкодер + декодер, как в оригинальном трансформере.

Итог: декодер — это **авторегрессивный генератор**, который учитывает и то, что уже сказал, и то, что ему передал энкодер.
